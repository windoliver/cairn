# Policy trace on every write and retrieval decision — design

- **Issue:** [windoliver/cairn#95](https://github.com/windoliver/cairn/issues/95)
- **Parent epic:** [#17](https://github.com/windoliver/cairn/issues/17)
- **Depends on:** [#94](https://github.com/windoliver/cairn/issues/94) — consent journal & async mirror (merged in PR #227)
- **Brief sources:** §14 Privacy and Consent · §5.1 Read path · §5.2 Write path · §8.0.b Response envelope · §6.3 Visibility floor · §4.2 Scope tuple

---

## 1. Goal

Every mutating verb (`ingest`, `capture_trace`, `forget`) returns a populated
`policy_trace` listing every gate that fired, in execution order, with a
`pass | deny | error` outcome and a body-free `detail`. Every read verb
(`search`, `retrieve`) populates `policy_trace` and a per-record `excluded`
list **only** when the request sets `explain: true`; the default response
remains byte-identical to today's wire.

The trace is the authoritative explanation for *why* a record was written,
rejected, redacted, kept, filtered, or deleted. Auditors and operators must be
able to debug those decisions without re-introducing the bytes the redactor
just removed.

## 2. Non-goals

- No new gates. Gates that already make decisions in the pipeline get exposed;
  we do not add new policy logic.
- No ReBAC graph (P2).
- No cross-vault federation (P2).
- No `lint` / `summarize` / `assemble_hot` traces — `lint` is owned by [#96];
  the rest are out of scope for v0.1.
- No persistent trace store. Traces live on the response envelope; an optional
  debug table is future work.

## 4. Architecture

### 4.1 Crate placement

- **`cairn-core`** — typed `policy_trace` module: `PolicyGate` (closed enum),
  `PolicyOutcome`, `PolicyDetail` (body-free enum), `PolicyTraceEntry`,
  `RecordExclusion` (PR2). `From` impls map existing pipeline outcome types
  (`Decision`, `RedactedPayload`, `FencedPayload`, `VisibilityPolicy`, scope
  check, forget-capability check, consent-journal-append result) to
  `PolicyTraceEntry`. `to_wire(&[PolicyTraceEntry]) -> Vec<ResponsePolicyTrace>`
  is the only mapping function; it is pure and exhaustive.
- **`cairn-cli`** — every affected verb composes gates as today, then pushes
  outcomes onto a local `Vec<PolicyTraceEntry>` and wires the vec into the
  envelope at the end. CLI parses `--explain` for `search`/`retrieve` (PR2).
- **`cairn-store-sqlite`** — no schema change.
- **`cairn-mcp`** — passthrough; the wire shape is generated by codegen.
- **`cairn-idl`** — PR1: no change. PR2: additive — `args.explain` on
  `search`/`retrieve` (default `false`); response field `data.excluded?`
  (present only when `explain == true`); new `record_exclusion.json` schema.

### 4.2 Boundaries that must stay intact

- `#![forbid(unsafe_code)]`; no `unwrap`/`expect` in `cairn-core`.
- `cairn-core` zero-deps invariant — `From` impls reference only existing core
  types.
- `BlockedAuditEntry` body-free pattern in `pipeline::filter::audit` is the
  model `PolicyDetail` follows.
- IDL is the single source of truth for wire shapes. `gate` stays an open
  string at the wire boundary; the producer-side `PolicyGate` enum is closed
  inside core.
- §3 storage authority: the database remains the source of truth. Traces are
  response artifacts, not stored records.

## 5. Types (canonical)

```rust
// cairn-core/src/policy_trace/mod.rs (new module)

/// Closed set of gates that can fire across all eight verbs.
/// `Display` emits the stable snake_case wire string.
#[derive(Debug, Clone, Copy, PartialEq, Eq, Hash)]
#[non_exhaustive]
pub enum PolicyGate {
    PresidioRedaction,        // §5.2 redact
    PromptInjectionFence,     // §5.2 fence
    FilterShouldMemorize,     // §5.2 should_memorize → Decision
    VisibilityFloor,          // §6.3 default_visibility
    ScopeCheck,               // §4.2 scope tuple
    ForgetCapability,         // §8 forget gate
    ConsentJournalAppend,     // §14 atomic journal write
    // PR2 — per-record exclusions on read verbs (--explain only).
    ReadFilterRelevance,
    ReadFilterStaleness,
    ReadFilterDedup,
}

#[derive(Debug, Clone, Copy, PartialEq, Eq, Hash)]
#[non_exhaustive]
pub enum PolicyOutcome { Pass, Deny, Error }

/// Body-free detail. Mirrors `BlockedAuditEntry` — every variant carries
/// metadata only, never raw bytes, source content, or record bodies.
#[derive(Debug, Clone, PartialEq, Eq)]
#[non_exhaustive]
pub enum PolicyDetail {
    None,
    DiscardReason(DiscardReason),                       // existing enum
    RedactionTagCounts(BTreeMap<RedactionTag, u32>),
    VisibilityFloor(Visibility),
    ScopeMismatch { required_tier: Tier },              // never echoes caller's actual scope
    ForgetMode(ForgetMode),
    ConsentKind(ConsentKind),                           // existing §14 enum from #94
    ErrorCode(&'static str),                            // stable code; never a free message
}

#[derive(Debug, Clone, PartialEq, Eq)]
pub struct PolicyTraceEntry {
    pub gate: PolicyGate,
    pub outcome: PolicyOutcome,
    pub detail: PolicyDetail,
}

/// PR2 only — per-record exclusion for caller-visible records filtered by
/// rank-and-filter. Tier-1 invisible records are filtered before this list
/// is built; their ids never appear here.
///
/// Fields are private. The only constructor is `RecordExclusion::new`,
/// which rejects non-`ReadFilter*` gates. External callers cannot use a
/// struct-literal `RecordExclusion { gate: ScopeCheck, … }` to bypass
/// the Tier-2-only invariant. Read-only accessors expose the data.
#[derive(Debug, Clone, PartialEq, Eq)]
pub struct RecordExclusion {
    target_id: TargetId,
    gate: PolicyGate,            // must be one of `ReadFilter*` (constructor enforced)
    detail: PolicyDetail,
}

impl RecordExclusion {
    /// Construct an exclusion. Panics on a non-`ReadFilter*` gate
    /// (programmer error / fail-closed against Tier-1 leaks).
    pub fn new(target_id: TargetId, gate: PolicyGate, detail: PolicyDetail) -> Self;
    pub fn target_id(&self) -> &TargetId;
    pub fn gate(&self) -> PolicyGate;
    pub fn detail(&self) -> &PolicyDetail;
}

/// Pure exhaustive mapping. Cannot fail.
pub fn to_wire(entries: &[PolicyTraceEntry]) -> Vec<ResponsePolicyTrace>;
```

`From` impls (one per gate, all in `cairn-core`):

- `From<&Decision> → PolicyTraceEntry` — gate `FilterShouldMemorize`,
  outcome derived from `Decision::Proceed | Discard(DiscardReason)`.
- `From<&RedactedPayload> → PolicyTraceEntry` — gate `PresidioRedaction`,
  detail aggregates spans into `RedactionTagCounts`. `Pass` when no spans;
  `Deny` only when paired with a `pii_blocked` filter decision upstream.
- `From<&FencedPayload> → PolicyTraceEntry` — gate `PromptInjectionFence`,
  outcome always `Pass` (fencing is non-blocking by design — it wraps,
  never rejects).
- `From<&VisibilityFloorOutcome>`, `From<&ScopeCheckOutcome>`,
  `From<&ForgetCapabilityOutcome>`, `From<&ConsentJournalAppendOutcome>` —
  same pattern.

A new pipeline gate that lacks a `From` impl fails compilation because
`to_wire` exhaustive-matches over `PolicyGate` variants.

## 6. Data flow per verb

### 6.1 `ingest` (PR1)

```
parse args → load source bytes → build CaptureEvent
  ┌─ redact()                  → push (PresidioRedaction, Pass|Deny, RedactionTagCounts)
  ├─ fence()                   → push (PromptInjectionFence, Pass, None)
  ├─ should_memorize()         → push (FilterShouldMemorize, Pass|Deny, DiscardReason)
  │    if Deny: emit rejected envelope, no store call
  ├─ default_visibility()      → push (VisibilityFloor, Pass, VisibilityFloor(v))
  ├─ scope_check(caller, v)    → push (ScopeCheck, Pass|Deny, ScopeMismatch{required})
  │    if Deny: emit rejected, no store call
  ├─ store.upsert() (WAL)      → if Err: push (ConsentJournalAppend, Error, ErrorCode)
  └─ on success                → push (ConsentJournalAppend, Pass, ConsentKind::Remember)
emit envelope { status, policy_trace, ... }
```

### 6.2 `capture_trace` (PR1)

Identical to `ingest` minus the `default_visibility` *decision* (capture path
uses fixed `session` floor) but still emits a `VisibilityFloor` entry with
that fixed floor for auditability — every gate that ran appears in the trace
even when it had no choice to make.

### 6.3 `forget` (PR1)

```
  ┌─ forget_capability_check(caller, target) → push (ForgetCapability, Pass|Deny, ForgetMode(mode))
  │    if Deny: emit rejected, no store call
  ├─ wal_op_apply(forget)      → push (ConsentJournalAppend, Pass|Error,
  │                                     ConsentKind::ForgetIntent | ErrorCode)
  └─ emit envelope
```

### 6.4 `search` / `retrieve` (PR2; `explain == true`)

```
parse args
  ┌─ scope_check(caller)       → push (ScopeCheck, Pass|Deny, ...)
  │    if Deny: trace = [ScopeCheck=Deny]; no store query; rejected envelope.
  │    `excluded` absent. No record-existence leak.
  ├─ store.query(scope)        → returns only records the caller IS allowed to see.
  │    Tier-1-invisible records are filtered inside the store query and
  │    never enter the candidate set; their ids never appear in the trace.
  ├─ rank_and_filter(candidates) → returns kept[] + excluded[{target_id, gate, detail}]
  ├─ aggregate per-gate entries (one PolicyTraceEntry per ReadFilter* gate that fired)
  └─ emit envelope { data, policy_trace, excluded: Some(excluded) }
```

When `explain == false` (default), no extra work runs: the verb emits
`policy_trace: []` and no `excluded` field. Wire is byte-identical to today.

### 6.5 Failure semantics (all five verbs)

- **Deny.** Normal verb outcome. Trace populated, status `rejected`, no store
  mutation. Exit code `1`.
- **Error.** Mid-pipeline failure. The gate that surfaced the error pushes
  `(gate, Error, ErrorCode)`; earlier entries stay so post-mortem can see how
  far we got. Status `aborted`. Exit code `1`.
- **Panic.** Forbidden in core (clippy deny). If reached, the process aborts;
  no partial trace is ever serialized.

## 7. Wire & IDL

### 7.1 PR1 — one additive IDL variant

`ResponsePolicyTrace` is already generated; verbs stop emitting `vec![]`.
The only IDL change in PR1 is appending one variant to the closed
`Capabilities` enum (`schemas/common/capabilities.json`):

```json
"cairn.mcp.v1.policy_trace"
```

PR1 re-runs `cargo run -p cairn-idl --bin cairn-codegen` and commits the
diff. The closed `gate` vocabulary is documented in
`docs/site/src/reference/policy-gates.md`, generated by `cairn-docgen` and
committed in PR1.

### 7.2 PR2 — three additive IDL fields

1. `verbs/search.json` — `args.explain: { type: boolean, default: false }`.
2. `verbs/retrieve.json` — same.
3. `verbs/{search,retrieve}.json` — response `data.excluded?: array of
   RecordExclusion`, present only when the request had `explain: true`.

```json
// schemas/common/record_exclusion.json (new)
{
  "type": "object",
  "additionalProperties": false,
  "required": ["target_id", "gate", "detail"],
  "properties": {
    "target_id": { "$ref": "target_id.json" },
    "gate":      { "enum": ["read_filter_relevance",
                            "read_filter_staleness",
                            "read_filter_dedup"] },
    "detail":    { "type": "string" }
  }
}
```

`gate` on `RecordExclusion` is a **closed** enum — per-record exclusions are
limited to the three Tier-2 read-filter gates. `gate` on `ResponsePolicyTrace`
stays **open** (`string`) so adding a new core gate does not break the wire.
Validation that a producer-side string came from `PolicyGate::Display` is a
producer concern, not a wire concern.

PR2 re-runs `cairn-codegen` and `cairn-docgen --write` and commits the diffs.
CI gates already enforce no-diff.

### 7.3 Backward compatibility

- `explain` defaults to `false` → existing callers see byte-identical wire.
- `excluded` is `skip_serializing_if Option::is_none` → absent when not
  requested.
- A snapshot test in `cairn-cli/tests/envelope_tests.rs` asserts byte-identity
  for the no-explain path against the existing snapshot.

## 8. Capability advertisement

`status` advertises the new `cairn.mcp.v1.policy_trace` capability via
the closed `Capabilities` IDL enum (see §7.1 — added in PR1). The
capability is included in every `status` response on builds that wire
the trace producers. Future gate-vocabulary breaks travel with the MCP
contract version (`cairn.mcp.v2.*`) — a fresh closed `Capabilities`
enum at that point — rather than as a `.v2` suffix on this capability,
matching the existing sibling pattern (`cairn.mcp.v1.search.keyword`,
`cairn.mcp.v1.extension.sessiontree`, etc., none of which carry an
embedded vocabulary version).

## 9. Logging & observability

The trace is a **response artifact**, not a log line. We do not duplicate it
into application logs.

- `tracing::debug!(gate = %g, outcome = ?o)` — single event per gate at
  `debug` level. Never `PolicyDetail` (`RedactionTagCounts` is body-free but
  is still authorized only for the response recipient).
- `tracing::info!` and above never see gate names.
- The doc comment on `PolicyTraceEntry` makes the rule explicit.

## 10. Security invariants (each test-enforced)

1. No raw record body, source bytes, or user text in any `PolicyDetail`
   variant — enforced by the type system; variants only carry metadata.
2. No `target_id` of a Tier-1-invisible record in `excluded` — store query
   filters before rank-and-filter produces exclusions.
3. `--explain` does not bypass `ScopeCheck` — caller without scope sees
   `[ScopeCheck=Deny]`, no candidates queried, `excluded` absent.
4. Default response (no `--explain`) is byte-identical to today's wire for
   read verbs (snapshot test).
5. `PolicyDetail` serialization is body-free regardless of variant — a
   JSON-walker test (same pattern as #94's `ConsentEvent` walker) asserts
   no `body|text|raw|command|url|content|payload` field name appears in any
   serialized trace.

## 11. Testing strategy

### 11.1 Unit (`cairn-core::policy_trace`)

- `From<&Decision>` round-trip for every `DiscardReason` variant.
- `From<&RedactedPayload>` count-aggregation correctness.
- `to_wire` exhaustive over every (`PolicyGate` × `PolicyOutcome` ×
  `PolicyDetail`) combo via proptest.
- Body-free invariant: proptest-generated `PolicyTraceEntry`, asserts
  serialized JSON contains zero banned key names.
- `Display` for `PolicyGate` is stable — snapshot the full enum.

### 11.2 Integration — PR1 (`crates/cairn-cli/tests/policy_trace_*.rs`)

- `policy_trace_ingest.rs` — golden gate sequence per fixture: clean text,
  pii-only text (deny on filter), policy-blocked, scope-denied, wal-failure.
  Each fixture asserts the exact ordered `Vec<gate_string>`.
- `policy_trace_capture_trace.rs` — same shape.
- `policy_trace_forget.rs` — capability-pass, capability-deny, wal-error.
- `policy_trace_no_body_leak.rs` — feed a body containing literal markers
  `BODY-MARKER-AAAA` / fake SSN / fake email; assert serialized response
  contains zero of those bytes anywhere.
- `policy_trace_capability.rs` — `cairn status` advertises
  `cairn.mcp.v1.policy_trace`.

### 11.3 Integration — PR2 (`crates/cairn-cli/tests/explain_*.rs`)

- `explain_search_default_byte_identical.rs` — snapshot the default search
  response wire bytes; assert identical to the existing snapshot.
- `explain_search_visibility_silent.rs` — fixture vault containing `private`
  records; caller has `session` scope. `search --explain` returns
  `policy_trace = [scope_check=pass]`; `excluded` either absent or contains
  zero ids of the private records (assert by id-set).
- `explain_search_filtered_visible.rs` — caller has visibility, records pass
  scope but are filtered for staleness; `--explain` returns those record ids
  in `excluded` with `gate = read_filter_staleness`.
- `explain_retrieve_*.rs` — same matrix on retrieve.
- `explain_unauthorized_debug.rs` — caller without read capability for the
  scope sends `--explain`: gate is `scope_check=deny`, `excluded` absent,
  no record ids leaked.

### 11.4 Property tests

- `cairn-core/tests/policy_trace_round_trip.rs` — proptest on gate sequences,
  round-tripping `to_wire → ResponsePolicyTrace → JSON → ResponsePolicyTrace`.
- The body-free walker is property-driven.

### 11.5 Snapshot tests (`insta`)

One snapshot per (verb × outcome class). Reviewed via `cargo insta review`.

### 11.6 Existing test upgrade

`cairn-cli/tests/envelope_tests.rs` upgrades the wire-shape assertion from
`is_array` to `is_array && !is_empty for {ingest, capture_trace, forget}`.

### 11.7 Eval harness

No new eval pieces in #95 — that lands with #96 (`lint`).

## 14. Out of scope

- Persistent trace store / debug table (future).
- Trace-driven regression eval gates (#96).
- Cross-vault federation of traces (P2).
- ReBAC graph (P2).
- `lint` / `summarize` / `assemble_hot` traces.

## 15. Open risks

- **Gate ordering churn.** Snapshot tests pin per-verb ordered gate sequences;
  any pipeline reorder requires a snapshot update + reviewer sign-off. This is
  the right friction — ordering is part of the contract.
- **`detail` field growth.** `PolicyDetail` is `#[non_exhaustive]`; new
  variants are a minor change. Each new variant must be reviewed for
  body-freeness and added to the JSON-walker allowlist.
- **Capability lock-in.** Once `cairn.mcp.v1.policy_trace` ships, the
  closed `PolicyGate` vocabulary is part of the v1 wire contract. Adding
  a new gate variant is a `#[non_exhaustive]` minor change, but a
  vocabulary *break* (rename, semantic shift) travels with the MCP
  contract version — `cairn.mcp.v2.*` carries a fresh closed
  `Capabilities` enum.
